# JCS2 Windows launcher

`JCS2Launcher.exe` is a small native Win32 launcher for a user-owned Android 9 / API 28 Google APIs x86 runtime. It resolves every configured path relative to its own EXE (including spaces and Unicode), starts one configured guest, scopes every ADB invocation to a dedicated server port and serial, waits at most 90 seconds for boot, installs the configured APK split set, optionally starts the configured UHID controller, and launches only `com.trueaxis.jetcarstunts2`. `--dry-run` validates and prints the resolved plan without starting an emulator or touching a device.

## Setup

On the Windows PC, stage the official emulator, platform-tools, and API-28 Google APIs x86 system image under `sdk\`, copy `launcher.ini.example` to `launcher.ini`, and place the user-owned original five APK splits under `assets\original`. All configured paths are UTF-8 and relative to the EXE. The launcher writes the AVD pointer/config directly from the staged image (no SDK manager or JRE is required), preserving an already-owned userdata state and refusing to claim arbitrary state. Run `powershell -ExecutionPolicy Bypass -File prepare-personal-runtime.ps1` to validate the staged files, or let the EXE perform that first-launch preparation. No downloads or account/device actions are performed during preparation. Build from a Visual Studio Developer PowerShell with `powershell -File build.ps1`, then run `JCS2Launcher.exe`.

The example uses RAM 1536 MB, software/SwiftShader graphics, explicit QEMU `-m 1536`, `-accel auto` (never assumes KVM), WHPX where available through the official emulator, and `-qemu -net none`. Guest Wi-Fi/data/radio disablement and route verification happen before APK installation; Bluetooth disablement is best-effort for Android 9. The launcher does not enable administrator settings, root apps, reset, restore private AVDs, or change host security. Use another `adb_port`/`emulator_port` pair if 5040/5596 (or emulator port + 1) is occupied; no process outside this launcher's owned guest is stopped.

The APK entries are intentionally configurable, but exactly five splits are required and no entitlement/unlock result is promised. Installation is skipped only when a SHA-256 state marker and `pm path` verification both match; no account wipe or private AVD access is performed. The launcher preflights both loopback ports plus the emulator console companion port before mutation, uses a dedicated ADB port, assigns the suspended emulator and all launch subprocesses to a kill-on-close Job Object, guards every ADB mutation with child liveness and exact serial identity, disables guest radio/data services, verifies routes and non-root ADB, and uses one `install-multiple` transaction. Configure `controller_exe`, `controller_helper_jar`, and `controller_mapping` together to start the controller after guest isolation and before the game. The launcher passes absolute host paths, waits at most 30 seconds for a live child plus a matching `{serial,transport:"uhid",device_id}` ready JSON marker, and fails closed on missing/invalid/late readiness or controller exit during play. The marker is unique per session and controller output is written to a regular owned log.

Linux native tests execute the shared quoting/INI/path/boot/port logic. The checked-in PE is cross-compiled with the staged llvm-mingw toolchain, statically links the C/C++ runtime, and uses only Win32, Winsock, and BCrypt system APIs; physical Windows emulator/WHPX behavior remains unverified here.
